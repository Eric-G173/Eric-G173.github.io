# Introduction
Completing coursework throughout the computer science curriculum was monumental in helping me understand the fundamentals of computer science and what it truly meant to be different roles such as a software engineer. The diverse amount of information I have learned through classes such as database systems in DAD-220, and full-stack development in CS-370 have left a great impact on me and what I am capable of achieving with coding. I feel that I am fully capable of acting as the engineer or the architect of a software, and be able to properly diagnose issues in code and build a full system for clients. When it comes to team collaboration, I had multiple situations where I had to collaborate with a team member or client regarding code. One example is in my CS-340 class (Client/Server Development), where I had to implement new features to a database over time, and eventually create a single-page application to display information about dogs being rescued, including geological information such as maps. This was completed in artifact 1, but during the course I had to constantly communicate with the instructor about my changes and get approvals to the design of the project. The main team collaboration I had was from an ASU class I took on engineering. There we had a group of 5 people, in which each of us would design a robot blueprint, but also C++ code with it. We would then overlook each other’s products and pick one that aligns the most with our goal. For practice with stakeholder communication, I could align this with my 3rd artifact the most, which is my DAD 220 class (Intro to structured databases). The main part of the project was taking data from a database and transforming it into a paragraph to explain to a non-technical stakeholder. This helped me practice how to respond to people who are not technical, but have them still understand the database and how it functions. The second artifact I chose most aligned with DSA’s. This artifact was the creation of an encryption algorithm to encrypt data being transferred. This involved creating a hash algorithm to perform the encryption, and I was able to learn the structure that goes into creating one. The artifact enhanced this by allowing me to try this in two separate languages, which further increased my foundational understanding of algorithms. For software engineering and database, the best class for that was CS-465 (Full-stack Development 1). This class involved the creation of a frontend and backend in the MEAN stack, while also configuring a mongo database to wire into the website. In this class I was able to get the full experience of software engineering by understanding client requests (new travel additions, price updates, etc.) and being able to update that on the frontend, backend, and in the database. For security, I would again think of artifact 2 which handled hash encryption. This artifact and the class behind it helped me understand why software security and encryption is important. It changed my mindset on how to view software or write one.

<br>
In general, each artifact chosen for this portfolio helps showcase a different skill and foundational level of computer science knowledge that can be usable in any software related field. These artifacts helped cover the core areas of the computer science field such as security, full-stack, and how to connect different pieces of code together such as backend to frontend. Before starting this degree, I thought software came down to just coding and making an idea work. This degree has taught me about all the different principles and fundamentals you must consider to get a software working. Artifact 1 helped showcase the importance of having organized and clean code that can be referenced. It occurs to me now that adding comments and keeping your code containerized and separate is important for making it readable and easy to update. Splitting up one giant file into multiple components made it easier for me to find and update different areas of the project. Artifact 2 was focused more on the algorithm side of computer science. It taught me that a lot of problems with long code files can be solved with simple algorithm replacements. Artifact 2 shows this well as originally I thought the encryption process would be hundreds of lines of code. Turns out in python, it only requires around 5-6 lines of code to get a fully functioning hash encryption. It was amazing what was possible at such a small scale, and how algorithms can simplify complex projects into more digestible parts. Artifact 3 was in my opinion the combination of what I have learned. This turned what was a word document into a fully functional SPA with a react frontend and a python backend. The database was also custom made based off previous parts of the old project. This involved me creating all portions of the stack by hand, without any code already being given to me like in the other artifacts. Through this artifact, I was able to fully connect a full-stack application as well as a database, and get it functionally running. The premise around this idea is also important, as my goal was to make a database easier to read for non-technical users, and I believe I solved that problem with the creation of this enhancement.
